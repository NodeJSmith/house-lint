### AC#8 verify grep omits `_normalize_contents_glob`

Design AC#8 (design.md:74) requires six things deleted from `discovery.py`:
`_prefix_pattern`, `_escape_gitignore_literal`, `_strip_unescaped_trailing_whitespace`, `_collapse_double_star_run`, `_normalize_contents_glob`, and the constant `IGNORE_EVERYTHING`.

T02's Prompt correctly lists all six for deletion (T02-replace-flattening-pipeline.md:31-36, including `_normalize_contents_glob` explicitly at line 35).

But T02's Verify item for AC#8 (T02-replace-flattening-pipeline.md:104) is:

```
grep -n '_prefix_pattern\|_escape_gitignore_literal\|_strip_unescaped_trailing_whitespace\|_collapse_double_star_run\|IGNORE_EVERYTHING' src/house_lint/discovery.py
```

This pattern omits `_normalize_contents_glob`. If the standalone function is left behind (e.g., an implementer keeps it out of caution, or a merge mistake reintroduces it), this Verify check would still report AC#8 as satisfied — a false pass. Confirmed the standalone function currently exists at `discovery.py:171` (`def _normalize_contents_glob(pattern: str) -> str:`), so this is a live check, not a hypothetical.

**Fix:** add `_normalize_contents_glob` to the grep alternation, e.g.:
```
grep -n '_prefix_pattern\|_escape_gitignore_literal\|_strip_unescaped_trailing_whitespace\|_collapse_double_star_run\|_normalize_contents_glob\|IGNORE_EVERYTHING' src/house_lint/discovery.py
```
Note the grep must still tolerate the transformation's *inline logic* living inside `_build_patterns` (T01) and the `_CONTENTS_GLOB` regex constant possibly staying (T02 line 28 says keep `_CONTENTS_GLOB` if reused) — the check should confirm no `def _normalize_contents_glob` definition remains, not that the substring never appears (comments referencing the old name are explicitly allowed elsewhere in the same Verify item's parenthetical, and that allowance should extend to this addition).

T02's Prompt (line 79) is unambiguous:

T02's own Verify item for AC#1 (line 101) is consistent with this: "xfail marker removed, test produces correct result."

But T02's Verify item for **FR#1** (line 97) says:

> `uv run pytest tests/integration/test_gitignore_parity.py -v` passes — the test `test_negated_directory_pattern_re_includes_a_directory_git_descends_into` now produces the correct result (underlying test passes, **even though xfail marker produces xpass**)

This directly contradicts the Prompt/Focus/AC#1-Verify instructions in the same file: it describes a state where the xfail marker is still present and produces XPASS — which, under `strict=True` (confirmed at `test_gitignore_parity.py:303`), is a **test failure**, not a pass. **Fix:** reword T02's FR#1 Verify item to match AC#1's, e.g.: "`uv run pytest tests/integration/test_gitignore_parity.py -v` passes — the xfail marker is removed and `test_negated_directory_pattern_re_includes_a_directory_git_descends_into` passes as a regular test."
